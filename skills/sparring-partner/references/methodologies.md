# Methodologies

A working toolbox for each phase. Pick what fits the moment — do not run the whole list at the user. Each entry is: **name → how to run it → when it earns its keep.**

## Framing (Phase 1)
Make sure the idea is aimed at the *right problem* before any effort goes into solving it.

- **First principles** — Strip the problem to the facts that must be true and rebuild from there, ignoring "how it's usually done." Use when the idea inherits conventions nobody has questioned.
- **Problem restatement** — Write the problem five different ways; the wording you settle on changes which solutions look obvious. Use when the goal feels fuzzy.
- **5 Whys (on the goal)** — Ask "why" up the chain until you hit the real motivation. Use when the stated goal might be a proxy for a deeper one.
- **Jobs-to-be-done** — Ask "what job is this being hired to do?" Use for products/features where the real need hides behind a feature request.
- **Constraint mapping** — List every constraint, then mark each as hard (physics/law/budget) or soft (habit/assumption). Most "hard" constraints turn out soft. Use to find room nobody knew existed.
- **"What would have to be true?"** — For the idea to be worth doing, what conditions must hold? Then check each. Use to expose load-bearing assumptions early.

## Divergence (Phase 2) — no judgment here
Maximize the number and variety of options. Suspend all evaluation.

- **Analogy / biomimicry** — "Who else solves a structurally similar problem?" (nature, other industries, other fields). Imports non-obvious mechanisms.
- **Assumption reversal** — Take a core assumption and flip it ("what if it were free / instant / illegal / reversed?"). Use when ideas feel stuck in one frame.
- **Extreme scaling (10x / 0.1x)** — "How would this work at 10x the scale/budget/users? At one-tenth?" The extremes reveal new designs. Breaks linear thinking.
- **SCAMPER** — Substitute, Combine, Adapt, Modify, Put-to-other-use, Eliminate, Reverse. A mutation checklist. Use when you have one idea and need ten.
- **"How might we…"** — Reframe each problem as an open "how might we" question to invite many answers. Keeps the space open.
- **Combine unrelated domains** — Force two unrelated concepts together and see what falls out. Escapes obvious territory.
- **Worst possible idea** — Deliberately design the *worst* solution, then invert each bad property. Use when thinking has gone too cautious to be creative.

## Convergence (Phase 3)
Narrow honestly to the few options worth pursuing.

- **Decision / Pugh matrix** — Score options against weighted criteria derived from the success definition. Use when several options are plausible and preferences are fuzzy.
- **Trade-off table** — For each option, list what you gain and what you give up. Makes hidden costs explicit.
- **ICE / RICE** — Rank by Impact × Confidence × Ease (RICE adds Reach). Use for prioritizing many small bets.
- **Forced ranking** — No ties allowed; rank everything. Use when "they're all good" is hiding a real preference.
- **Satisfice vs. maximize** — Decide whether "good enough, clears the bar" beats "theoretically best." Avoids analysis paralysis.

## Critical / pressure-test (Phase 4)
Try to break the surviving idea before reality does.

- **Pre-mortem** — Imagine it's later and the idea failed; write the post-mortem *now*. Surfaces risks people won't volunteer up front. The single highest-value pressure test.
- **Inversion** — "How would we *guarantee* this fails?" Then avoid those paths. Often easier than asking how to succeed.
- **Steelman, then attack** — Build the strongest version of the idea, then attack *that* — never a strawman. Honest and disarming.
- **Second-order consequences** — "And then what?" Repeat. Catches effects that appear one or two steps downstream.
- **Outside view / base rates** — "How often do projects of this type actually succeed?" Counters inside-view optimism.
- **Falsifiability** — "What evidence would change your mind?" If nothing would, it's a belief, not a plan.
- **Chesterton's fence** — Before removing or replacing something, establish *why* it exists. Use when the idea deletes an existing thing.
- **Red team** — Take the role of an adversary trying to defeat or exploit the idea. Use for security, competition, abuse cases.
- **5 Whys (root cause)** — For a problem the idea must fix, dig to the actual cause so the fix isn't cosmetic.

## Synthesis (Phase 5)
- **Graft the losers** — Pull the single best element from each rejected option into the winner. Rejected ideas usually had one good part.
- **Decision record** — Capture the decision, the rationale, the alternatives rejected, and what would reopen it. This is the spine of the living document.
